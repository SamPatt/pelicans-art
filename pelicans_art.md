# pelicans.art Plan

## Concept

A community site for sharing AI Improv Theater assets and published skits. Users create content locally using their own editor, LLM, and TTS, then submit to a public GitHub repo. pelicans.art serves as a static gallery and player.

## Architecture

- **No database, no auth system** — GitHub handles identity and storage
- **No multi-tenant editor** — users run the editor/server locally
- **No hosted LLM or TTS** — users bring their own compute
- **Static site** — browse, viewer, and player are all client-side HTML/JS

## Submission Flow

1. User runs the editor locally with their own TTS and LLM
2. Creates sprites, backgrounds, props, skits
3. Publishes skits (bundles all assets + MP3 audio into self-contained JSON)
4. Forks the public repo, adds content to `community/` directory, submits PR
5. GitHub Action validates the submission (file sizes, SVG safety, schema)
6. On merge, GitHub Action regenerates the browse index

## Community Directory Structure

```
community/
  sprites/<username>/<sprite-name>/
    front.svg
    meta.json
  backgrounds/<username>/<bg-name>/
    landscape.svg
    portrait.svg (optional)
  skits/<username>/<skit-name>.json
  published/<username>/<skit-name>.json
```

## Pages

| Route | Description |
|-------|-------------|
| `/browse` | Gallery of community-submitted sprites, backgrounds, and skits. Reads from a static JSON index auto-generated by GitHub Actions. |
| `/viewer` | Detail page for individual assets — full-size SVG preview, metadata, author. Linked from browse. |
| `/player` | Skit player (already exists). Loads published skit JSON and plays with embedded assets and audio. |

## Published Skit Format

Self-contained JSON with all assets embedded as base64:

```json
{
  "meta": { "title": "...", "description": "..." },
  "stage": { "background": "apartment", "orientation": "landscape" },
  "cast": {},
  "props": {},
  "script": [],
  "assets": {
    "sprites": { "man-suit-front": "data:image/svg+xml;base64,..." },
    "spriteMeta": { "man-suit": { "type": "human", "voice": { "id": "javert" } } },
    "backgrounds": { "apartment": "data:image/svg+xml;base64,..." },
    "props": { "handgun": "data:image/svg+xml;base64,..." },
    "propMeta": { "handgun": { "holdOffset": [0, -10] } },
    "audio": { "line-0": "data:audio/mpeg;base64,..." }
  },
  "publishedAt": "..."
}
```

Audio is MP3 (64kbps mono via ffmpeg), not WAV. A 10-line skit is ~300KB total.

## Hosting Options

- **GitHub Pages** — free, auto-deploys from repo, good for static content. 1GB soft limit.
- **Existing VPS** (65.108.53.114) — more flexible, already running. Makes sense if any server-side logic is needed.

GitHub Pages is the simpler choice since everything is static.

## GitHub Actions

**On PR submission:**
- Validate SVG files (no embedded scripts)
- Check meta.json against schema
- Verify file sizes are reasonable
- Auto-generate preview images for PR review

**On merge to main:**
- Scan `community/` directory
- Build JSON manifest with titles, authors, thumbnails
- Commit updated index file

## What Users Need to Run Locally

- The editor (`sprite-editor.html` + server)
- A TTS server (pocket-tts or compatible)
- An LLM API key (for AI-assisted sprite/skit generation)
- ffmpeg (for MP3 audio in published skits)
